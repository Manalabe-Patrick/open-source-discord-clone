# Discord Clone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a portfolio-grade Discord clone (servers/channels, real-time chat, presence, roles, DMs, friends, image attachments) that demonstrates full-stack and real-time/WebSocket skill.

**Architecture:** An npm-workspaces monorepo with a `packages/database` package (Prisma schema + client) shared by two apps: `apps/web` (Next.js 14+ App Router — UI, auth, all non-realtime CRUD) and `apps/socket-server` (Node + Socket.IO — real-time messaging, typing, presence), both backed by one Supabase Postgres database.

**Tech Stack:** Next.js (App Router) + TypeScript + Tailwind CSS, NextAuth/Auth.js (Credentials + Google OAuth), Prisma ORM, Supabase (Postgres + Storage), Socket.IO, Vitest, npm workspaces.

## Global Constraints

- Real-time transport is Socket.IO, run as a standalone Node service (`apps/socket-server`) — Vercel does not support long-lived WebSocket connections, so it cannot live in `apps/web`.
- Database is Postgres via Supabase, accessed through Prisma from a single shared `packages/database` package — never a second, divergent schema.
- Auth is NextAuth/Auth.js using JWT session strategy (not database sessions) — `apps/socket-server` must be able to verify the session token itself via `NEXTAUTH_SECRET`, with no HTTP call back to `apps/web`.
- Exactly three roles per server: `OWNER`, `ADMIN`, `MEMBER`. No custom permission bitfields.
- DM conversations are created lazily on first message, never on friend-request acceptance.
- No voice/video, no message edit history, no reactions/threads — out of scope per spec.
- Tests use Vitest. Business logic (permission helpers, validators) and API routes are unit/integration tested; realtime socket behavior is tested manually per phase (documented steps, not automated).
- Deployment target: `apps/web` → Vercel, `apps/socket-server` → Railway or Render, both phases deferred to the final phase of this plan.

This plan covers **Phase 0 (scaffolding) through Phase 2 (servers & channels CRUD)** — the foundation. Phases 3–9 (realtime chat, presence, roles, DMs, friends, attachments, deployment) are written as separate follow-on plan documents once this foundation is built and verified, so each stays a manageable, independently reviewable size:
- `2026-08-28-discord-clone-phase3-5-realtime.md` (to be written next)
- `2026-08-28-discord-clone-phase6-9-social-polish.md` (to be written after that)

import express from 'express'
import cors from 'cors'
import { createServer as createHttpServer } from 'http'
import { Server as SocketIOServer } from 'socket.io'

export function createServer() {
  const app = express()
  app.use(cors())

  app.get('/health', (_req, res) => {
    res.json({ status: 'ok' })
  })

  const httpServer = createHttpServer(app)
  const io = new SocketIOServer(httpServer, {
    cors: { origin: process.env.WEB_ORIGIN ?? 'http://localhost:3000' },
  })

  return { app, httpServer, io }
}

const isMain = process.argv[1] && process.argv[1].endsWith('index.ts')
if (isMain) {
  const { httpServer } = createServer()
  const port = process.env.PORT ? Number(process.env.PORT) : 4000
  httpServer.listen(port, () => {
    console.log(`socket-server listening on port ${port}`)
  })
}

  session: { strategy: 'jwt' },

      clientId: process.env.GOOGLE_CLIENT_ID ?? '',
      clientSecret: process.env.GOOGLE_CLIENT_SECRET ?? '',

      name: 'Credentials',

        if (!user || !user.passwordHash) return null

      return token

import bcrypt from 'bcryptjs'
import { prisma } from '@repo/database'

export async function POST(request: Request) {
  const body = await request.json()
  const { email, password, name } = body as { email?: string; password?: string; name?: string }

  if (!email || !password || !name) {
    return NextResponse.json({ error: 'Email, password, and name are required' }, { status: 400 })
  }
  if (password.length < 8) {
    return NextResponse.json({ error: 'Password must be at least 8 characters' }, { status: 400 })
  }

  const existing = await prisma.user.findUnique({ where: { email } })
  if (existing) {
    return NextResponse.json({ error: 'An account with that email already exists' }, { status: 400 })
  }

  const passwordHash = await bcrypt.hash(password, 10)
  const user = await prisma.user.create({
    data: { email, name, passwordHash },
    select: { id: true, email: true, name: true },
  })

  return NextResponse.json(user, { status: 201 })
}
